## 0.1.11 使用次数与协议升级

累计使用次数 = 字幕提取启动数 + 视频总结启动数。分别显示成功、失败和取消次数，日期按北京时间记录，跨日开始/完成分属各自日期。任务异常终止可能没有结束结果。缓存命中的总结计一次，连接测试、权限拒绝、未启动的重复点击、后台刷新、查看历史和复制导出不计。旧版从未记录次数，不能补回。

客户端 `/v1/usage` 升级到 `schema: 2`：五个严格允许的字段为 `schema`、`installation_id`、`app_version`、`active_days`、`operation_days`。`operation_days` 最多 31 条，每条只有 `day`、`extract`、`summary`；后两项分别是四个非负整数，顺序为启动、成功、失败、取消，每日单项上限 10 亿。`active_days` 可为空，两个日期列表不可同时为空。正文最大 8192 字节。`/v1/access` 和旧版 `/v1/usage` 的 `schema: 1` 保持兼容，后台不会把旧版活跃记录换算成功能次数。

上传的是每安装、每日期的累计快照；服务端逐项取最大值，只将正差额增加到累计表。原子事务避免并发、重复、乱序上报增加重复次数；客户端保存最近 31 个自然日及确认快照，失败至少等待 15 分钟。每日记录保留 90 天，安装累计继续保留，过期上报不再次入账。

Python/SQLite 启动时自动创建新表。Cloudflare 部署前应用新增的 `0002_operations.sql` 迁移，然后部署 Worker；不要重新创建 D1 或设置管理口令。现有安装编号、日期、版本、权限和口令不变。后台显示累计/今日次数、功能结果、每日明细及每个安装编号的累计次数。

仅上报匿名操作类型与次数，不包含视频链接、字幕、笔记、模型设置、费用或密钥。次数用于了解使用情况，不能当作模型调用数、计费凭据或精确人数。

## 统计口径

| 指标 | 含义 |
|---|---|
| 累计首次启动 | 成功上报的随机安装标识数量 |
| 今日新增 | 首个有效使用日期为今天的安装实例数 |
| 日活 DAU | 今天在前台打开/使用 APP 的安装实例数，按日期去重 |
| 月活 MAU | 包含今天在内的近 30 个自然日内活跃安装实例数，跨天去重 |
| 版本分布 | 每个安装实例最近一次成功上报的版本 |

日期按北京时间计算。配置后台的新版默认统计，不弹出参与提示；未接入后台的旧版和未成功补报的离线安装不计入。卸载重装或清除数据会生成新标识，无法跨设备识别同一人，也不等于 APK 下载量或精确人数。离线补报可能修正历史新增日期。权限检查也会更新版本和当日活跃，因此版本分布通常在下一次前台检查后更新。

统计安装、活跃以及字幕提取和总结的功能次数，不统计视频、字幕、笔记、模型名称或费用。统计数据库保存随机标识的 SHA-256 散列、版本及日期，不写入原始标识、IP、User-Agent 或请求正文；本部署没有启用 HTTP 访问日志，网络服务仍需临时处理来源地址。活跃日期保留最近 90 天并在接收新上报时清理，安装散列及首次/最近日期继续保留以提供累计值。同时保存管理员设置的使用权限与停用原因；0.1.9 不再提供统计参与开关。

## 部署到自己的服务器

免费试用可以使用新增的 [Cloudflare Workers + D1 部署教程](cloudflare/README.md)，Windows 即可部署和管理，不用让电脑一直开机。Cloudflare 版保持同一 APP 接口，避免每分钟重复写库；当前 workers.dev 在用户手机直连失败，需更换入口并重新验收。Python/SQLite 和 D1 的数据库独立，旧数据不会自动迁移。

### Windows 查看和管理

升级后若本机后台仍在运行，请关闭原运行窗口后重新启动，以加载新版代码；口令和数据库保留。

Windows 可以通过浏览器管理已部署的公网后台，不需要在管理电脑安装 Linux、Docker 或 Python。管理口令由后台部署者设置，不是模型 API Key，也不是 `.env.example` 里的示例值。

本机体验已提供 `start-windows.cmd`：安装 Python 3.10+ 后双击即可启动并打开浏览器，首次自动生成随机管理口令；运行窗口会显示口令，`show-password.cmd` 可再次查看。保持运行窗口开启，按 Ctrl+C 或关闭窗口停止服务，数据和口令保留。源码/后台 ZIP 中的启动器默认将私有文件放在 `%LOCALAPPDATA%\SuiKanStatistics`，不包含在源码和分发包里。

本会话 outputs 目录的「打开统计后台.cmd」「查看管理口令.cmd」快捷入口则指定本项目的 `work/statistics-admin` 私有目录，两者使用同一套口令和数据。不要把这个私有目录分享给使用者。

**本机模式只监听 127.0.0.1，方便查看和联调，不接收其他手机的数据。** 给其他人分发时，仍需部署可公开访问的 HTTPS 服务并配置 APK。电脑只是管理端时无需一直开机；若选择在电脑上承载服务，则需要持续运行并另行配置公网 HTTPS。本机启动器使用 Python 开发服务，正式公网部署按下面的方式处理，参见 [Python 官方说明](https://docs.python.org/3/library/wsgiref.html)。

### 公网接收服务

需要 Linux 服务器、Docker Compose 和解析到该服务器的域名，允许 80/443 入站。以下命令在本目录运行。

1. 上传本目录，复制 `.env.example` 为 `.env`。
2. 设置 `SUIKAN_STATS_HOST` 为自己的域名（不带协议、路径或端口）。使用至少 32 字符的随机管理口令替换示例，只保存在服务器，不能填入 APK。可在服务器运行 `python -c "import secrets; print(secrets.token_urlsafe(36))"` 生成。
3. 启动：

```sh
docker compose up -d --build
```

Caddy 自动申请/续期 HTTPS 证书。只有 HTTPS 代理公开端口，数据库服务不直接暴露。管理页面为 `https://你的域名/`，健康检查为 `/healthz`。输入 `.env` 中的管理口令即可查看统计；数据接口只接受 Authorization 请求头，口令不在 URL、本地存储或 APP 中。页面刷新或退出会清除内存中的口令。

部署前确认自己的域名在目标用户网络上可访问。Docker 镜像、HTTPS 证书签发和公网连通性尚未在本次本地测试中验证；按 [Caddy 自动 HTTPS 文档](https://caddyserver.com/docs/automatic-https) 配置 DNS、端口和证书条件。

## 将地址编入 APP

SDK CLI 构建（其他参数按项目 README 填写）：

```powershell
.\build-apk.ps1 -StatisticsUrl 'https://你的域名/v1/usage' -SdkRoot 'Android SDK目录' -JdkHome 'JDK 17目录' -BuildBase '.\.local-build' -OutputApk '.\dist\SuiKan-0.1.11.apk'
```

`-StatisticsUrl` 只改变本次构建的资产，不修改源码默认配置。不带参数则读取 `app/src/main/assets/usage-statistics.json`（当前为空）。Android Studio / Gradle 构建需先将同一 JSON 文件中的 `endpoint` 设置为真实 HTTPS 地址。

仅填写公开上报地址，不填管理口令。地址必须是 HTTPS，路径为 `/v1/usage`，不得带账号、查询参数或片段。APP 不跟随统计请求的重定向。地址为空/无效时不显示统计弹窗和开关，也不联网统计；配置后自动上报并检查使用权限，不弹出参与确认或提醒；没有新增手机权限。

**先用配置后的测试包在手机上启动，确认后台累计数增加、同一天重复打开日活不增加，再开始分发。** 原版 APK 地址为空，Cloudflare 接入测试包尚未通过大陆手机直连验收。

## 本地运行与测试

开发服务仅绑定本机，不用于公网部署：

```powershell
$env:SUIKAN_ADMIN_TOKEN='仅供本机测试的随机口令，至少32字符'
$env:SUIKAN_DB='本机私有目录/usage.sqlite3'
python statistics/server.py --port 18766
```

生产使用 Docker 中的 Gunicorn，不能把开发服务直接暴露到公网。管理页不依赖外部 CDN、字体或统计服务。

```powershell
python -m unittest discover -s statistics -p 'test_*.py' -v
.\tests\run-usage-tests.ps1 -JsonJar 'org.json 测试JAR' -JdkHome 'JDK 17目录'
```

服务端测试覆盖去重、并发、离线日期、月活边界、重启持久化、鉴权、输入限制、限流和保留期。客户端测试覆盖默认上报、旧版迁移、跨天、离线、重启、补报、并发、有限队列与权限缓存；安卓 HTTPS 联调覆盖自动上报、停用拦截及恢复。

## 在后台停用与恢复

1. 登录网页后，下方「用户使用权限」显示安装编号、版本、首次/最近使用日期、当前状态与原因，每页 50 条。
2. 用户可在配置后台的 APP「设置 → 复制安装编号」提供编号；在网页输入完整编号或小写十六进制前缀筛选。
3. 点击对应记录的「停用」，核对编号，填写不超过 200 字的可选原因并确认。APP 再次检查权限后会阻止新的字幕提取和总结，并显示原因。已有笔记、字幕及模型设置保留，仍可查看/复制/导出。
4. 点击「恢复」并确认，APP 下一次成功检查后恢复任务。前台每分钟检查；任务启动前使用最多一分钟的缓存，不强行中断已经执行的任务。

检查接口为同一域名的 `/v1/access`，仅发送随机安装标识与版本，返回可用状态和原因。权限检查会登记当日活跃，与每日统计去重。无需在 APK 放管理口令。后台先升级到此版本，再分发 0.1.9；旧版 APK 不支持停用。

临时网络故障沿用最近有效权限。首次未获得权限时允许使用；已停用的安装断网、重启仍停用，恢复需再次连到后台。重装/清除数据会产生新编号，修改开源客户端也可绕过，因此适合普通使用管理，不能作为付费、反作弊或不可绕过的授权。管理员列表只识别安装实例，无法判断真实姓名或同一人的多设备。

旧版统计数据库启动时自动增加独立权限表，既有数量和记录保留；原管理口令无需更换。升级前请按下面的方法备份。

## 运维与限制

- 数据保存在 Docker `usage-data` 卷。重建容器不清除数据；只有确实要删除数据库及证书时才执行 `docker compose down -v`。
- 使用 SQLite backup API，或停止统计容器后备份整个数据卷，避免只复制活动 WAL 数据库的主文件。恢复后保留既有安装散列才能继续去重。
- 管理口令只在服务器设置，不上传 `.env`、数据库、TLS 私钥或 APP 签名私钥。不要添加包含来源 IP / 请求正文的访问日志，否则需同步修改隐私披露。
- 上报接口公开，限制字段、UUID 格式、正文最多 8KB（管理和权限请求最多 2KB）、31 个日期、每安装标识每分钟 12 次、进程每分钟 6000 次请求。当前为单进程轻量部署，这些限制不能阻止伪造安装标识，不适合计费、奖励或反作弊。大规模分发需增加入口防护和数据库容量管理。
- 连接/读取各最多等待 5 秒，在独立线程执行。失败至少间隔 15 分钟，在下次前台使用时重试；不在后台定时唤醒手机，每日补报不占用模型请求线程。权限请求在任务工作线程或独立统计线程执行，连接/读取各 3 秒，成功与失败均缓存 60 秒，避免每次任务重复等待。最多补报最近 31 个日期，活跃按天去重，功能任务开始/结束后补报累计快照，持续前台跨天会记录新日期。


## Android 本机 HTTPS 联调复现

以下仅为开发测试，不部署到公网。需要测试依赖 `cryptography`，测试口令和本机 CA 只用于隔离的测试服务，不放入生产 APP。

1. 在项目根目录运行 `python tests/statistics_fixture.py --directory .local-build/usage-fixture-run1`。每轮使用新的目录；脚本不会删除已有数据库。HTTP 18767 显示示例数据，HTTPS 18768 从空数据库接收手机请求。
2. 使用 `-StatisticsUrl https://localhost:18768/v1/usage` 构建单独的测试主 APK。保留正式 APK 的地址为空，或配置自己的真实 HTTPS 地址。
3. 用 `tests/build-tests.ps1 -BuildInfo <测试构建信息JSON> -TestAssets .local-build/usage-fixture-run1/assets` 构建测试 APK，安装同签名的主 APK 和测试 APK。
4. 模拟器运行 `adb reverse tcp:18768 tcp:18768`，再运行 `adb shell am instrument -w -r -e mode enabled com.suikan.app.tests/com.suikan.app.UsageHarness`。默认空地址的正式 APK 使用 `-e mode disabled`。

测试 CA 只加入 Instrumentation 所在进程的临时 SSLContext，测试结束恢复默认信任。生产 APP 的系统证书信任和 HTTPS 校验没有放宽。测试结束关闭本地服务、移除端口转发，并保管正式 APK 的签名私钥。
